# 时间账本重构设计

日期：2026-11-17。状态：本地开发，尚未部署。

## 约束与模型

仅复用已有项目、标签、任务系统，不增加面向用户的活动分类维度。时间记录可以有项目，也可以只有标签；至少选择一项归属。不因项目缺失自动推断「生活事务」，不创建「无项目」「日常」等占位项目。

| 活动       | 项目               | 标签       | 核算                 |
| ---------- | ------------------ | ---------- | -------------------- |
| 睡觉       | 留空               | 睡眠       | 计入时长，不折算金额 |
| 跑步       | 留空               | 运动       | 按记录时单价折算     |
| 阅读 C++   | 上位机学习（可选） | 阅读       | 按记录时单价折算     |
| 开发 Aster | Aster              | 编码、专注 | 按记录时单价折算     |

任务仍可没有项目和标签；从任务开始计时须先给任务补项目或标签，或在账本录入时选择本次归属。关联任务会带入项目、标签，但明确清空本次项目后不能重新暗中继承。账本的本次归属不改变任务 UUID、项目或状态。

`#睡眠` 是普通标签，录入快捷勾选会添加该标签；它同时触发已有睡眠计价与提醒策略。底层 `categoryId` 保留以兼容已有记录、规则和睡眠政策，不新增分类选择器或分类统计页。显式的旧 API 分类仍保留兼容。

## 页面与流程

只保留「记录 / 统计」两个页面入口；原 weekly / reports 地址仍映射到同一统计组件。

记录页：日期与补记 → 已确认时长 / 时间折算 / 待核对时长 → 当前计时或开始表单 → 核对与待定位（按需展开）→ 时间线 → 已保存计划（按需展开）。

- 计时始终从当前时刻开始，选择历史日期不改变这一点；历史活动通过补记录入。
- 补记共用一个表单：知道起止时间则定位入账；只记得时长则先保留待定位估记。回忆估算的边界标注「大约」。
- 已保存计划可以单独回看、手动开始、调整或归档。暂停保留剩余额度；保存和调整不自动开始。实际停止点取用时额度与最晚结束时间中的较早者。
- 开始计划与保存计划是两次写入，开始失败后刷新服务端状态，保留已创建计划供检查；同一草稿重试复用已创建计划，避免重复创建。
- 待确认的时间部分、睡眠候选和待定位估记不加入正式总量。部分已确认的记录按已确认部分计算，不把整段简单排除。
- 确认、修正、未知结果核对、撤销仍走现有版本化服务端接口。失败后刷新状态；错误保留在原表单，避免丢失草稿。
- 快速切换日期时旧请求不能覆盖新日期；加载期间不展示另一日期的记录。

统计页：周期选择（周 / 月）→ 已确认汇总 → 每日趋势（时长 / 金额）→ 项目 / 标签分布与可展开明细 → 关联现金支出（按需展开）。

## 统计口径

总时长包括有项目与无项目记录，按活动事实只计一次。只统计已确认且已定位部分，待核对部分另列，待定位估记不混入。

项目表只显示真实项目。总量减去项目表之和得到未关联项目小计，明确说明已经计入总量，并提供按标签查看；不把该小计伪装成一个项目。

标签包括所有记录，按活动 ID 和切片边界去重后聚合。历史无标签记录可显示「未设标签」。多标签分别累计，标签分组不能相加为总量；每日趋势和总量仍按活动去重。

时间折算使用记录当时的单价快照，睡眠不折算。Bills 现金支出单独呈现，不分配给标签，不与时间金额混成主汇总指标。

## 兼容与边界

不批量改写历史项目或分类，不依据名称合并实体；真实项目「睡眠」与无项目的 `#睡眠` 记录保持独立。之后修改任务项目不重写旧活动的项目快照。旧分类系统仅用于现有兼容与计价策略。

界面使用固定明细列，大屏限制内容宽度；小屏改为时间、活动、操作及第二行数值，标签可换行。弹窗限制在视口内并滚动，日期与起止时间在手机分行，触屏输入保持 16px。

验证使用独立模拟数据，不写入真实账本；尺寸检查覆盖手机、iPad 和桌面。实际历史数据的归属不会在本次重构中自动清洗。
