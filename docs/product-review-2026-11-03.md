# Aster 产品检查 · 2026-11-03

后续进展：恢复、导出、重复任务入口、备注、计时异常提示、完整备份导入、标签多选及 TinyCast 新入口已在 [2.5](release-2.5.md) 完成。下文保留当时的检查记录。

定位：个人使用，围绕最多三个当前目标推进工作。功能增加应减少整理和重新决策的负担。

## 当前已具备

- Focus 三项目限制、完成条件、手动指定下一步，以及 Later／Completed。
- 嵌套项目、分支移动／改名／删除、描述、独立颜色。
- 任务增改、完成／重新打开、删除、搜索、日期、优先级和标签。
- Q 快速输入及属性识别；列表／看板切换、可自定义栏目、拖动和移动菜单。
- 原生 Taskwarrior 筛选器、标签管理、收藏。
- 开始／停止任务、Timewarrior 计时、每日精力与补充精力。
- Light／Dark／System、手机 PWA、TinyCast 共享工作区。
- 完成及看板移动的 Undo、版本冲突保留草稿、未知写入不自动重试。

## 本次 UI 调整

1. Focus 去掉任务行与区块之间重复的分隔线。
2. 侧栏项目的选中背景覆盖展开按钮、项目名称和菜单所在整行；选中后悬停保持同一背景。
3. 任务行增加轻微悬停反馈，键盘进入任务行时能看到开始／停止入口。
4. 桌面任务弹窗收敛到 560px；表单控件统一 36px、14px 字号；标题、正文及操作区左右对齐。
5. 手机任务表单使用单列，保留 44px、16px 控件；短屏内部滚动，保存按钮留在底部。
6. 看板 Move 按钮去掉暗色模式中多余的实心背景；列区域可以用键盘聚焦和横向滚动。
7. 保持 List／Board 相同的内容宽度、原配色、项目颜色和业务数据结构。

这里的“缺少”指产品界面没有提供或缺少完整流程，不表示 Taskwarrior 底层没有对应能力。回顾、备注和恢复仍应围绕三目标工作流，不把项目改造成综合管理平台。

## 可靠性问题先于扩展功能

- Timewarrior 读取失败当前返回空数组，容易与“确实没有用时”混淆。应提供计时来源异常状态；不能把读取失败当成零用时或正常精力值。
- 精力耗尽目前会阻止开始任务。建议保留既定规则，另行讨论是否允许显式临时覆盖，并明确“精力是规则估算值”；本次没有改动此业务规则。
- 现有发布备份是运维能力，不能替代用户可操作的导出和恢复。恢复操作仍需保留 UUID、任务状态与看板位置，并进行真实持久化验证。

## 暂不建议增加

多人协作、复杂 OKR／评分、更多统计仪表盘、AI 自动拆解和任务层级、完整日历，都可能增加整理负担。提醒／推送仅在确有到时提醒需求时再做；截止日期显示不等于后台通知已经可用。

## 建议顺序

先做“误删恢复／导出”和“重复任务入口”，解决可靠性与重复录入；再补任务备注，随后按真实使用情况决定是否需要 Focus 回顾与 Upcoming。已经有任务、项目、看板、计时和精力，不宜同时扩张所有方向。

## 检查边界

UI 在隔离测试数据上检查桌面、390×844 手机和 320×640 短屏，覆盖明暗主题、列表／看板、任务编辑及键盘入口。源码修改仅涉及网页表现层，不改任务字段、项目状态、计时和精力规则。真实线上数据不作为测试数据。
